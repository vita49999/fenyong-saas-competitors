Tapfiliate：追踪与佣金管理，明确结算和转账边界

1 产品概述与商业模式

官方验证 Tapfiliate 提供联盟推广追踪、伙伴管理、佣金、报表、素材、自动化及集成，适用于电商、SaaS 和订阅场景。定价与能力表（T1）、追踪产品（T2）。

分析推断 其主要形态是商家自建联盟项目的管理工具，核心业务是把外部转化变成可审核、可结算的佣金，实际付款可以由商家或外部通道完成。产品的 Payment 记录不能直接理解为银行转账。

官方验证 当前月付页面列 Launch $89、Scale $179、Enterprise 定制。Launch 有1项目、50联盟成员、每月5,000点击及500转化等限制；Scale 扩大配额及高级佣金、Trolley 等能力（T1）。待验证 超额、币种、税费和最终合同另验。

4 官方真实页面截图与交互分析

官方验证 来源：结算与付款文件。已视觉核验，可见 Settle all balances、截止日期、Export 和逐伙伴余额。

分析推断 结算工作集中在余额列表，批量动作适合周期付款；正负金额用颜色区分，能提示超付。风险在于“结算”会让余额扣减，而钱仍可能尚未转出。操作确认应明确外部付款步骤并标出缺失收款资料的成员。待验证 当前弹窗的默认选项和批量排除逻辑需实测。

官方验证 同一官方文章的伙伴端截图，可见待审核与负佣金金额。分析推断 商家和伙伴两端均展示负余额有利于透明解释；但负数为何产生需要可下钻到原始佣金、退款和结算记录，仅显示金额不足以消除争议。

5 对象、关系、状态、规则、异常、权限、资金、API

5.1 概念模型

分析推断 Conversion 与 Commission 应区分；一次转化可涉及不同佣金逻辑。余额不是不可变账本，修改已批准佣金会影响它，需核验是否能追溯金额变更。

5.2 归因和文档冲突

官方验证 官方集成说明写默认 Cookie45天，并给配置范围及最高365天；营销追踪页又描述1天到 lifetime。集成说明，2026-09-10（T3）、营销页面（T2）。

待验证 这可能由套餐、版本或营销措辞造成，不能选择一个范围写成通用承诺。应查看当前租户 Program 设置与销售确认。Cookie 支持也不等于拒绝 Cookie、跨设备或浏览器限制下必定归因。

5.3 审核、退款与资金

官方验证 默认追踪转化 Pending；退款、退货、作弊、自购、重复及测试订单可拒绝。已支付佣金拒绝后扣减当前余额，部分调整可修改佣金金额。Stripe/WooCommerce 智能集成提供退款自动处理开关。退款和作废（T5）。

官方验证 标准流程 Settle 会扣余额、生成 CSV；它不表示款项已从商家账户转出，也无法证明收款到账。未填写收款资料的人若被纳入结算，仍可能标 Settled；可 Cancel 恢复余额（T4）。分析推断 Balance 公式中的 paid/settled 是系统登记语义，应以外部支付凭证确认真实资金。

官方验证 Trolley 连接从 Scale 起、首笔订阅付款后可用，试用期间不可用；结算数据传给 Trolley，仍需在 Trolley 完成支付。取消涉及两系统处理。Trolley，2026-01-16（T6）。待验证 原生 Hands-Free 服务仍有 Coming soon 文案，不因“将在2026年”推定已上线。

5.4 API、权限和系统

官方验证 API 自动化的官方顺序是：获取余额及收款信息→通过支付方 API 实际付款→在 Tapfiliate Create a Payment 登记。REST付款流程（T7）。分析推断 “创建 Payment”本身不是转账。

官方验证 REST 文档有 PATCH /1.6/commissions/{commission_id}/ 和批准/拒绝等能力，示例使用 X-Api-Key。REST（T8）。待验证 文档部分示例存在 Api-Key/X-Api-Key 名称差异，接入时应以当前接口实际鉴权说明验证，不复制任意样例。限流、幂等、密钥范围和权限矩阵未实测。

6 产品经营与商业模式

分析推断 Launch 的规模配额与 Scale 高级佣金/付款集成形成升级路径。除 SaaS 订阅，还需考虑超额及外部支付服务费用；只比较软件月费会遗漏运营和对账成本。自建联盟工具的价值主要来自降低追踪和结算管理成本，伙伴招募质量仍依赖商家运营。

官方验证 定价页列的 Scale 自动付款是 Trolley，原生 Hands-Free 项目仍写 Coming soon（T1）。待验证 不将路线图能力作为采购可用能力。

7 产品经理可借鉴机制

机制 原因与价值 局限
佣金审核后形成余额 分析推断 先确认结果、再汇总付款 要区分审核和到期风险
正负余额同屏 分析推断 让超付可见，支持未来抵扣 不代表钱已追回

8 结论与待验证项

分析推断 Tapfiliate 的研究重点应是佣金与余额管理的可解释性，以及“Settled≠到账”。不宜以默认流程没有转账就写成完全不支持自动支付，也不宜把未来原生服务视为已交付。
