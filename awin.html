Awin：联盟网络中的验证、应付与付款

1 产品概述与商业模式

官方验证 Awin 连接广告主和 Publisher，提供伙伴发现、推广、报表、佣金规则和支付。广告主套餐为 Access、Accelerate、Advanced。广告主产品页（A1）。

分析推断 Awin 同时提供平台和网络组织能力，研究时不能仅把它视为一套供商家自建联盟的 SaaS。其价值包含发现与连接伙伴、约定交易验证规则、跨广告主收益管理。广告主、Publisher、代理机构和网络平台有不同责任。

官方验证 英国定价页观察值：Access £99 + VAT/月，加交易额3.5% tracking fee；Accelerate £199 + VAT/月起，加2.5%；Advanced 定制报价。伙伴佣金另由广告主设定。英国广告主定价（A2）。价格不可推广至全球合同。

4 官方页面与交互分析

官方验证 官方2026冬季版本发布页介绍新的广告主 Dashboard、关键指标、建议与待办，并提供演示。官方版本发布与演示（A8）。

官方验证 来源为上述A8官方版本发布页。这是官方营销合成展示图，已视觉核验，可见活动摘要、优惠码、日期和 Publish campaign，不是本次登录后台操作截图，也不能充当 Earnings Summary 或交易验证页截图。分析推断 创建与发布两个动作分离，有利于先确认活动配置再公开；当前产品是否有发布前检查及撤回，仍待实测。

截图完成度：已有官方Campaign展示图，并补充下方Classic商品分类映射真实截图；收益与交易验证页仍待补。

分析推断 根据 A3 官方交互说明，收益组件把颜色与任务绑定：绿色表示可进入下一批付款，黄色提示距离门槛的差额，红色提示收款信息阻塞，并提供设置入口。这比只有金额卡片更适合自助排障。应保留文字原因，避免仅用颜色表达。

分析推断 A4 的交易报告将付款状态和交易验证状态分别筛选，支持解释“Approved 中同时有已付与未付”。拒绝原因可悬停或导出，有利于逐单沟通。待验证 移动端原因查看、筛选持久化、复杂币种提示和异常修复后的即时反馈尚未实测。以上是文档交互分析，非截图观察。

5 对象、关系、状态、规则、异常、权限、资金、API

5.1 概念模型

分析推断 Programme 的市场和合同边界重要；网络账户、广告主计划、Publisher 参与关系应区分。实际关联基数及内部字段未验证。

5.2 状态和规则

官方验证 交易先 Pending review，由广告主验证后 Approved 或 Declined；Approved 不等于 Payable，后者需要网络支付处理完成。达到门槛且收款资料正确后进入付款批次。交易状态与付款过程（A3；2026-07-09 更新）。

官方验证 验证时间因广告主而异；平台显示的 Validation Period 是历史平均值，不是保证时限；Auto Validation Period 可以为 None。验证周期（A5）。分析推断 平均周期、自动批准规则和约定账期是三个概念，报告不把“60天自动批准”推广到全部计划。

官方验证 交易报表可查看手工 Bonus、查询等类型，Approved 视图包含已付和未付。交易报告（A4）。

5.3 资金责任与异常

分析推断 付款涉及广告主、网络与 Publisher 的多方链路，交易有效性只是可付的一个条件；网络处理、门槛、币种和收款资料均可能影响发款。真实资金责任须依地区合同和具体支付方案核实，不能由状态推断平台对所有广告主信用兜底。

5.4 权限、API 和系统

官方验证 A7 指出广告主 API 通常需 Accelerate/Advanced 或多计划，Conversion API 等有例外；Zapier 连接使用 API token、账号类型、计划/Publisher ID 和时区。API 集成说明。待验证 未完整列出交易验证接口、签名、限流、重试和权限枚举。

分析推断 需分别测试广告主、Publisher、代理机构及团队成员，尤其是“能查询报告”与“能验证交易/修改账户/付款”的分离。API 支持与套餐权益是不同问题。

6 产品经营与商业模式

分析推断 Awin 的网络供给与数据规模有助于伙伴发现，软件自动化和服务深度形成套餐升级。交易额比例费用使成本跟业务增长相关；商家预算必须同时计算平台费、tracking fee、伙伴佣金与可能的服务费。

官方验证 英国 Access 页面示例：£100 销售、伙伴6%佣金时，伙伴得£6、Awin tracking fee £3.50（A2）。分析推断 该 tracking fee 基数是销售额，不是伙伴佣金的3.5%，二者成本差异显著。待验证 跨市场价格、退款退费、税项及特殊行业替代费率需按合同验证。

8 结论与待验证项

分析推断 Awin 最值得借鉴的是多方联盟网络中的验证、可付与实际付款分离。它与自建联盟 SaaS 的比较必须纳入伙伴网络和费用结构，不能只比功能数量。

优先级 验证场景 验收证据
P0 同一 Approved 交易到 Payable 到 Paid 三阶段条件、责任方、时间记录
P0 付款资料错误与修复 阻塞原因、审核和后续批次
P0 部分退款/已支付后拒绝 佣金、tracking fee 及余额变化
P1 自动验证 None 与有期限计划 实际策略、超期处理
P1 多币种与最低门槛 各币种独立账单及付款
P1 后台静态截图与角色对照 真实页面、时间、版本和演示录屏
