# 有赞：把社交推广嵌入订单与售后

> [官] 研究主线是微商城“分销员”；供货分销平台、群团购和导购为相邻产品，不共用全部规则。证据等级及研究边界见 [阅读说明](00-阅读说明与完成度.md)。

## 1 产品概述与商业模式

[官] 分销员通过招募、分享和等级激励帮助商家扩展销售；有赞提供商城内的订单、客户和佣金管理能力。[产品介绍](https://www.youzan.com/chanpin/fenxiaofeiyongglxt)（Y1）、[使用教程](https://help.youzan.com/displaylist/detail_5_5-2-31720)（Y2）。

[析] 与单独的广告联盟追踪工具相比，其优势在于推广、交易、售后均在同一商城业务内，可以把“谁带来客户”和“什么时候允许结佣”直接关联。购买方是商家，操作方为运营和财务，受益方为分销员，支付订单的消费者是归因对象。分销员不因获得佣金自动成为商品供货商。

[官] 招募门槛中的指定商品、自购金额、消费笔数等能力涉及进阶能力包；没有证据支持本报告给出一个适用于全部商家的统一价格。[成为分销员的方法](https://help.youzan.com/displaylist/detail_4_4-1-24948)（Y3）。

## 2 端到端业务流程

[析] 下图是依据官方规则重构的核心链路，不是后台状态枚举。

```plaintext
[商家配置招募/绑客/商品佣金/结算]
                    |
                    v
[招募或导入分销员] -> [分享链接/二维码/海报]
                                    |
                                    v
                         [访问 -> 绑客规则判断]
                                    |
                                    v
                          [消费者下单并付款]
                                    |
                       +------------+------------+
                       |                         |
                 [售后退款]                [交易完成]
                       |                         |
              [结算前扣除退款]        [按结算方案等待]
                       +------------+------------+
                                    |
                         [自动结算 / 人工线下结算]
                                    |
                         [分销员查看收益 -> 提现]
                                    |
                       [清退后保留既有佣金访问入口]
```

| 业务动作 | 功能承接 | 解决的痛点 | 证据 |
|---|---|---|---|
| 让员工/客户参与推广 | 后台添加、导入、招募链接、邀请 | 人员进入渠道成本高 | [官] Y3 |
| 明确客户归属 | 有效期、保护期、允许抢客设置 | 多人争抢同一客户 | [官] Y4 |
| 形成差异化激励 | 分销员等级、不同佣金比例 | 统一激励缺乏成长空间 | [官] Y2 |
| 避免售后前过早支付 | 结算时间方案 | 退款后佣金难追回 | [官] Y5 |
| 退出后清偿历史收益 | 保留分销员中心/零钱提现入口 | 身份终止与债权混淆 | [官] Y6 |

## 4 官方真实页面截图与交互分析

![有赞官方帮助截图：配置个人中心的分销员入口](attachments/youzan-withdraw.png)

来源：[清退后如何提现](https://help.youzan.com/displaylist/detail_5_5-1-19559)。[官] 本图是官方帮助文章内截图，展示页面装修中配置入口；不是本次登录后台的操作结果，截图素材本身早于文章更新时间。

[析] 入口配置让商家可以决定个人中心展示的功能，但“看不到入口”容易被误解为“没有收益”。清退后提现依赖仍可访问的分销员中心，说明导航设置会影响资金权益的可达性。值得借鉴的是保留退出后的历史收益访问；可优化的是在清退操作前提示入口、认证和可提现余额，降低人工找入口成本。[待] 是否已有清退前余额检查、批量提示和独立历史佣金页，需租户验证。

[析] 绑客规则同时包含有效期、保护期和抢客触发，建议实测时观察是否实时展示例子：客户先点 A、保护期内再点 B、最终下单时归谁。仅从文档不能确定表单是否能充分帮助商家预判结果。

## 5 对象、关系、状态、规则、异常、权限、资金、API

### 5.1 概念对象与关系

[析] 逻辑对象模型：

```plaintext
商家/店铺 1 -- N 分销员
分销员 1 -- N 客户绑定记录 -- 1 客户
分销员 -- 等级/试用任务
分销员 -- 邀请关系 -- 分销员
订单 1 -- N 商品行 -- 佣金计算结果
订单 -- 售后退款 -- 佣金调整
佣金结果 -- 结算 -- 收益账户 -- 提现记录
```

绑定关系和邀请关系应分别理解：前者判断客户业绩归属，后者涉及邀请激励；“等级”也不等于上下级。内部表、字段主键、关系历史保留方式未验证。

### 5.2 决策规则与状态

[官] 绑客可永久或限时；允许抢客、保护期不允许抢客、通过链接下单抢客等是不同选项。重复访问原分销员链接可重新计算有效期。[Y4](https://help.youzan.com/displaylist/detail_4_4-1-39927)。

[官] 2022-06-20 结佣 FAQ 给出的基数是实付金额去除运费、退款等，结算前退款减少基数；自动结算后不支持商家线上追回。结算可按交易完成或售后结束条件，卡券有核销选项。[Y5](https://help.youzan.com/displaylist/detail_13_13-1-36489)。[待] 文档较旧，当前不同商品及套餐的到账时间、费用和退款追偿需要复验，不能把示例“发货后7天”当成所有订单 SLA。

[官] 试用任务未完成并不阻止佣金正常结算。[Y7](https://help.youzan.com/displaylist/detail_4_4-1-62540)。[析] 身份生命周期与应付款生命周期分离，避免考核失败吞掉既有收益。

| 异常 | 已知处理/风险 | 尚待验证 |
|---|---|---|
| 结算前部分退款 | [官] 退款部分不计佣（Y5） | 商品行优惠分摊、舍入 |
| 结算后退款 | [官] FAQ 提示已结算佣金可能不受影响（Y5） | 不同方案是否新增追偿能力 |
| 分销员清退 | [官] 仍有提现路径（Y6） | 后续未结算订单是否继续结算 |
| 未完成认证 | [官] 零钱中可能无提现入口（Y6） | 材料失败、审核时间与重提 |
| 同时点击多个链接 | [官] 依绑客设置处理（Y4） | 并发、跨端、覆盖历史 |

[官] 更详细的2024-07-18结算文档确认：商家余额不足或系统失败时保持待结算，有余额后自动重试；可按分组/标签或指定分销员采用不同结算方式；会员价无佣金是可选规则。人工结算分组不能沿用自动个税代缴能力。[Y9](https://help.youzan.com/displaylist/detail_5_5-2-31738)。[析] 因此结算异常既可能是订单条件未满足，也可能是资金余额不足，应分开解释。

### 5.3 权限与资金

[析] 店铺规则设置、人工结算和客户关系调整均会影响收益，权限验收应覆盖“能看收益”与“能改归属/结算”分离。[待] 当前分销模块角色矩阵、金额阈值审批、操作日志导出未完整验证。不可把通用商城角色能力直接当成本模块保证。

[析] 消费者货款、商家可用余额、分销佣金、分销员提现是不同层次。自动结算与人工线下结算有不同付款责任；“已计算”不是“已结算”，“已结算”也需要结合具体提现渠道判断到账。

### 5.4 API 与系统机制

[官] 官方招募文章明确支持通过有赞云开放接口导入分销员（Y3）。[待] 本次未获得稳定可读的分销接口全量契约，不列猜测的接口名。需验证 token 授权范围、分销员新增/查询、绑定变更、佣金明细、退款通知、限流及重复导入处理。[析] 接口接通的验收对象应是“同一笔订单能对到分销员、佣金和退款”，而不只是返回成功。

## 6 产品经营与商业模式

[析] 商城是交易基础，分销员是增长组件。能力包形成分层销售，商家拥有越复杂的招募和激励需求，越可能需要进阶配置；推广规模扩大后也增加了对订单、客户和资金模块的依赖。该机制可以增强续费价值，但付费边界不清会抬高方案评估成本。

[待] 分销员模块单独收入、活跃分销员规模、商户留存率和当前支付服务费未获可核验数据。没有用宣传案例推定平均 ROI。衡量价值应观察有效分销员率、净成交额、退款后净佣金、结算纠纷率，而不是仅看注册人数。

## 7 产品经理可借鉴机制

| 机制 | 原因 | 价值 | 局限 |
|---|---|---|---|
| 绑客有效期与保护期分开 | [析] 服务关系与短期拉新竞争不同 | 同时保护长期服务和再激活 | 规则组合多，需要例子和变更预览 |
| 结算时机贴近售后 | [析] 收益确定需要等待退货风险消退 | 减少追偿 | 延后到账降低推广者现金体验 |
| 退出仍可访问收益 | [析] 身份终止不消灭历史权益 | 减少争议和客服成本 | 入口配置与认证仍可能阻断 |
| 试用考核与佣金分开 | [析] 激励兑现不能完全依附晋级 | 激励可信、降低沉没劳动风险 | 对低质量流量仍需审核 |
| 商城内闭环 | [析] 单系统掌握订单与退款 | 归因、计佣解释更容易 | 跨平台订单仍需额外验证 |

## 8 结论与待验证项

[析] 有赞适合研究“关系分销怎样嵌入电商订单、售后和提现”。其重点不是广告点击算法，而是客户关系保护、人员激励与交易兑现。主要局限是产品线和套餐差异大，旧文档时间规则不能直接推广至所有场景。

| 优先级 | 验证用例 | 验收证据 |
|---|---|---|
| P0 | A 绑客、B 点击，分别处于保护期内/外并下单 | 归属前后记录与规则配置 |
| P0 | 100元订单部分退款，分别在结算前/后发生 | 商品行基数、佣金、调整和资金流水 |
| P0 | 有余额及待结算订单时清退 | 两类收益的最终去向 |
| P1 | 更换等级及商品佣金后查看旧订单 | 规则快照及是否重算 |
| P1 | 重复 API 导入同一人员 | 唯一标识、返回码、幂等结果 |
| P1 | 运营账号修改结算/客户关系 | 权限拒绝、审计及审批证据 |
