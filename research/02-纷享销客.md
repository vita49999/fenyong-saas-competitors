# 纷享销客：把销售流程向外部伙伴开放

> 研究主线为连接渠道及代理通；订货通、费用管理等邻接模块单列。不是把 CRM 的业绩统计解释为联盟佣金支付。

## 1 产品概述与商业模式

[官] 代理通将上游 CRM 能力延伸给代理商；下游可以保留自己的 CRM，并与多家厂商互联。它基于 PaaS 定制门户和业务过程，覆盖准入、客户报备、商机协作、报价和订单。[代理通概述](https://help.fxiaoke.com/83d7/91e3/a544/0a1f)（F1）。

[析] 其核心价值是跨企业业务协作：伙伴既是独立经营主体，又要遵循厂商的销售规则。购买方通常是上游企业，管理者是渠道经理，外部代理商是受控访问者。收入、利润、返利与推广佣金不是同一种业务对象。

[官] 官方渠道产品页还列出订货通、费用管理、销售预测、外勤、互联协同及伙伴学堂。[连接渠道产品页](https://www.fxiaoke.com/ap/product-outer/)（F2）。[待] 代理通独立报价、外部账号收费、实施费与模块组合价格未核实。

## 2 端到端业务流程

[析] 基于官方场景链路重构；订单后的具体收款、返利与 ERP 结算依实施范围。

```plaintext
上游渠道经理                         下游伙伴用户
[启用伙伴对象与应用]
       |
[添加企业/连接审核] <-------------- [接受邀请/申请连接]
       |
[配置外部角色、产品允销、门户]
       |
[分配线索/开放线索池] ------------> [领取/跟进/上报线索]
       |                                      |
[查重与报备审批] <----------------- [客户查重/客户报备]
       |                                      |
[销售流程、阶段任务] <------------> [商机报备/联合推进]
       |                                      |
[折扣/特价审批] <------------------ [报价/提交订单]
       |
[邻接：订货、库存、发货、回款、费用核销]
       |
[上下游报表与经营复盘]
```

| 业务动作 | 功能 | 痛点 | 证据 |
|---|---|---|---|
| 接入合作企业 | 企业互联、应用开通 | 重复建系统/邮件协作 | [官] F3 |
| 避免撞客 | 查重、客户报备、公海规则 | 伙伴抢客户、归属不清 | [官] F3 |
| 推进复杂销售 | 商机阶段任务与联合跟进 | 渠道销售过程不可见 | [官] F2/F3 |
| 控制价格 | 价目表、允销范围、折扣审批 | 越权销售和价格失控 | [官] F3 |
| 控制共享范围 | 外部角色/字段/数据权限 | 跨企业数据泄露 | [官] F4 |
| 提升伙伴能力 | 伙伴学堂、资料、简报 | 培训不一致、缺乏反馈 | [官] F1/F2 |

## 5 对象、关系、状态、规则、异常、权限、资金、API

### 5.1 对象与关系

[析] 下图是领域模型，不是数据库结构：

```plaintext
上游企业 -- 企业互联关系 -- 下游企业
   |                         |
合作伙伴档案                对接员工/外部角色
   |                         |
产品/价目表/允销范围 ---- 可访问业务范围
   |
线索 -> 客户/联系人 -> 商机 -> 报价 -> 销售订单
   |         |          |
线索池      报备记录     阶段任务/联合跟进
   |
互联流程/审批/消息/报表
```

[官] 上游配置开放对象与字段；外部角色决定操作和数据范围。下游不能自行修改上游的报备审批、产品允销和销售流程。[角色与边界](https://help.fxiaoke.com/83d7/91e3/a544/8179)（F4）。

### 5.2 状态与规则

[析] 需要分别分析企业连接状态、伙伴准入状态、客户报备审批状态、商机阶段、订单状态；不能合成一条“伙伴待审核→已成交→已付款”的状态链。[待] 各对象的正式枚举、驳回重提、保护期限和失效回收条件未获得完整文档，不给出虚构名称或天数。

[官] 官方场景说明上游负责线索池、公海与保有量、销售流程、价目表和允销范围；下游执行领取、报备、阶段推进和订单提交。[业务场景与流程](https://help.fxiaoke.com/83d7/91e3/a544/f329)（F3）。[析] 规则配置集中于上游，既有利于统一渠道政策，也增加实施设计和变更治理成本。

### 5.3 异常与权限

| 事件 | 可确认的机制 | 本次不能确认的细节 |
|---|---|---|
| 两伙伴报备同一客户 | [官] 查重和报备机制（F2/F3） | 谁先得、锁定多久、申诉权限 |
| 折扣超政策 | [官] 折扣/特价审批（F1/F3） | 阈值、会签、越级规则 |
| 看不到某对象 | [官] 核查应用开通及外部角色（F4） | 租户布局及字段具体组合 |
| 伙伴跨多个厂商 | [官] 多上游互联（F1） | 同名客户跨企业匹配与隔离 |
| 连接被解除 | [待] 未形成完整证据 | 历史报备、未完订单、数据留存 |
| 订货失败/退款 | [待] 邻接支付能力不能证明全部售后规则 | 预存款、返利、信用的冲正顺序 |

[析] 权限验收应采用“企业×人员×对象×字段×记录×动作”六维组合。能查看订单不应自然推导能看成本、能给折扣或能代审批。

### 5.4 资金与系统/API

[官] 订货通支持多种支付介质及信用、返利，但这是订货交易支付能力（F2）。[析] 渠道经销业务中的返利、预存款抵扣、信用赊销和代理推广佣金，应分别建模；代理通的线索到订单链路不能直接证明原生支付结算覆盖。

[官] 开发者手册中有渠道准入通知、签署和适用范围函数。[渠道管理功能](https://developer.fxiaoke.com/apl_v2/func-introduce/apl-func-scene/channel-management/)（F5；搜索可读摘要，正文拉取超时）。[待] 这些是 APL 场景函数，不能等同完整外部 REST API。对象查询、外部身份认证、增量事件、接口限流及 ERP 对账需补读对应开放平台文档并实测。

## 6 产品经营与商业模式

[析] CRM、PaaS 与伙伴协作形成扩展路径：先管理内部销售，再开放渠道和上下游流程，随后接入订货、培训、费用及外勤。复杂组织能获得流程一致性和数据贯通，也会承担配置、实施和持续维护成本。

[待] 未核验此模块独立订阅单价、伙伴账号是否免费、最低采购门槛和实施周期。不能把公开客户案例的经营提升直接归因于软件。价值指标应包括报备冲突率、线索响应时间、商机阶段停滞、伙伴活跃率、订单处理时长，而不是仅看 CRM 用户数。

## 7 产品经理可借鉴机制

| 机制 | 原因 | 价值 | 局限 |
|---|---|---|---|
| 上游配置、下游执行 | [析] 政策制定与业务执行分属不同企业 | 保持治理边界 | 配置错误会大范围影响伙伴 |
| 企业互联而非账号强合并 | [析] 伙伴需要独立经营并服务多厂商 | 降低组织迁移成本 | 数据同步与隔离复杂 |
| 报备嵌入销售流程 | [析] 渠道归属必须伴随推进责任 | 防止只占客户不推进 | 保护期、公海需精细策略 |
| 对象/字段/记录分层权限 | [析] “开放给伙伴”不是公开全部资料 | 兼顾协作和保密 | 权限排障成本较高 |
| 商机阶段任务校验 | [析] 结果指标无法解释过程阻塞 | 支持标准化推进 | 不同行业应允许差异化流程 |

## 8 结论与待验证项

[析] 纷享销客适合研究 B2B 渠道关系治理、报备、销售过程和跨企业权限。与电商分销及订阅联盟相比，其核心对象更接近企业、客户、商机和订单，而不是点击、转化与佣金。

| 优先级 | 验证场景 | 应取得的证据 |
|---|---|---|
| P0 | 两伙伴同时报备同一客户 | 查重范围、审批、归属和申诉记录 |
| P0 | 下游企业 A 访问 B 的客户或字段 | 服务端拒绝与角色配置 |
| P0 | 报备到报价、折扣、订单全流程 | 对象关联、流程交接、状态历史 |
| P1 | 伙伴停用/断开企业互联 | 未完业务、数据保留和权限收回 |
| P1 | 返利、预存款与信用混合支付退款 | 冲正账单及外部财务对账 |
| P1 | 外部接口批量同步客户和订单 | 身份、限流、幂等、失败补偿 |
