# 微盟：关系归属、商品奖励与分账配置

## 1 产品概述与商业模式

[官] 微盟微客分销支持招募推广者、配置推广商品及奖励、统计业绩、等级激励和分账；智慧导购则覆盖专属客户、任务、素材和导购激励。[分销设置](https://help.weimob.com/details/1847)（W1）、[智慧导购](https://cjdg.weimob.com/)（W2）。

[析] 本报告主线是微商城微客分销。微盟不是单一分销产品：知识付费推广员、微盟客分佣推广、分销市场和导购属于不同业务场景，角色、佣金上限、资金路径不能互相套用。购买者为商家，微客为推广者，导购是服务型销售角色，供货商是供应主体，三者不等同。

[官] W1 描述微商城标准版及以上、绑定认证服务号或小程序的开启条件。新微商城文档另有微客管理和门店推广资格。[微客设置](https://help.weimob.com/os/article/5363)（W3）。[待] 当前售卖套餐对应关系及价格需销售核验。

## 2 端到端业务流程

[析] 按微客分销主线重构，关系模式有分支：

```plaintext
[配置招募条件/微客等级/商品奖励/结算渠道]
                         |
                [申请/自动成为微客]
                         |
                    [分享链接/海报]
                         |
              +----------+-----------+
              |                      |
       [关系链优先]             [分享人优先]
       绑定及有效期             临时关系缓存
              +----------+-----------+
                         |
                [下单 -> 归属 -> 算奖]
                         |
              [退款调整 / 结算条件判断]
                         |
              +----------+-----------+
              |                      |
     [微信线上分账]           [线下应付账单]
              |                      |
      [失败转线下路径]        [审核/手工打款]
              +----------+-----------+
                         |
               [微客查看账户/提现记录]
```

| 动作 | 功能 | 痛点 | 证据 |
|---|---|---|---|
| 招募不同客户群体 | 会员/消费等申请条件 | 无效参与者过多 | [官] W1 |
| 决定归属偏好 | 关系链优先/分享人优先 | 长期服务与最后推广冲突 | [官] W1 |
| 指定商品奖励 | 默认/自定义、商品批量操作 | 全店一刀切佣金 | [官] W4 |
| 按门店控制推广 | 门店资格申请审核 | 跨店推广越权 | [官] W3 |
| 处理分账失败 | 转线下应付账单 | 异常资金无人接管 | [官] W1 |
| 提升导购执行 | 任务与素材、排行 | 服务和推广不连续 | [官] W2；邻接产品 |

## 5 对象、关系、状态、规则、异常、权限、资金、API

### 5.1 对象与关系

[析] 领域关系：

```plaintext
商户/门店 -> 微客推广资格 -> 微客/等级
微客 ---- 客户绑定关系 ---- 客户
微客 ---- 邀请关系 -------- 微客
商品/SKU ---- 默认或自定义奖励
订单行 ---- 奖励计算 ---- 分账/应付账单 ---- 提现
退款 ------ 奖励返还
```

[官] W1 明确绑定微客可能变化，邀请人确认后不再变化。二者不能共用一个“上级”字段解释。[析] 这是理解微客关系模型最重要的边界。

### 5.2 规则与版本冲突

[官] W1 的分享人优先模式描述24小时临时缓存关系，再访问其他微客分享可覆盖；关系链模式支持永久或限时、访问续期。模式切换有次日凌晨5点及每3天修改限制。[待] 当前租户版本与具体时区需确认。

[官] W1 中奖励可按数量或基数比例，退款按文档相应比例/退款额返还。切换奖励方式会重置默认和自定义奖励为0，需要重新配置。[析] 这是业务连续性风险：切换成功不代表新规则已经可用。

**[待] 资料内部及产品线差异必须保留：**

- W1 前部备注写“自购不得奖励”，后部又有“微客购买奖励”配置；应确认开关、版本及生效范围，不能给出统一“支持/不支持自购分佣”。
- W1 等级描述与 W4 默认阶梯数量不同，不采用一个通用等级上限。
- W4 的微客+邀请人比例上限，与 W5 微盟客分佣范围不同；两者是不同模块，不矛盾地拼成统一上限。
- W1 的成本价保护措辞不能被自行改写成通常理解的“利润保护公式”；触发基数与不发佣边界应实测。

### 5.3 资金与异常

[官] W1 线上分账需要微信支付授权和参数配置；维权期待分账资金被冻结可能延长商户收款账期。线上失败可转线下分账，线下在应付账单人工打款。[析] 应将“冻结货款”“应付奖励”“提现申请”“实际转账”分别追踪。

| 异常 | 已知处理 | 核验缺口 |
|---|---|---|
| 新增 SKU | [官] 自定义佣金要重配（W4） | 未配时是否阻止上架 |
| 奖励类型切换 | [官] 原配置重置为0（W1） | 历史未结订单采用哪版 |
| 微信分账失败 | [官] 转线下（W1） | 自动转入时间、重复支付防护 |
| 部分退款 | [官] 有奖励返还算法（W1） | 已提现后如何追回 |
| 关系模式切换 | [官] 历史绑定转临时有规则（W1） | 提醒、预览、审计 |
| 收款信息不全 | [官] 需微客完善（W1） | 阻断点及重试体验 |

### 5.4 权限、API 与机制

[官] W3 的门店推广资格及 W1 的客户信息展示开关，是明确的推广与隐私控制。[待] 商户内财务/运营权限、审核阈值、规则修改审计未完整核验。

[官] 微盟云公开文档列有 `weimob_distribution/distributor/create`，调用使用 ACCESS_TOKEN。[微客创建 API](https://doc.weimobcloud.com/detail?childMenuId=1&id=2833&isold=2&menuId=19&preview=true&tag=2259)（W6）。[待] 不据单接口推定全部佣金、提现、退款均可开放；版本、权限包、唯一标识、频控及错误码需补验。

## 6 产品经营与商业模式

[析] 微盟把分销嵌入商品、会员、门店和私域运营；导购扩展的是持续服务场景，微盟客扩展的是平台推广流量。其商业价值来自 SaaS 能力和场景扩展，但商家需要先判断购买的是哪个产品线。

[官] 2021-12-16 微盟客文档有从商品佣金扣取技术服务及营销费用的说明。[分佣推广](https://help.weimob.com/os/article/1013)（W5）。[待] 这是历史特定产品说明，不作为2026年微商城统一费率。本报告不引用统一“微盟佣金抽成”结论。模块收入、活跃微客、导购绩效改善及当前套餐报价没有独立验证。

## 7 产品经理可借鉴机制

| 机制 | 原因与价值 | 局限 |
|---|---|---|
| 绑定关系与邀请关系分离 | [析] 服务客户和招募推广者是两种贡献，解释不同收益 | 业务“上级”称谓容易混淆 |
| 线上失败落到人工账单 | [析] 给异常资金确定接管人和入口 | 必须防重复付款并保留原失败原因 |
| 奖励可货币化或权益化 | [析] 支持不同品牌激励成本结构 | 切换会影响余额口径和历史规则 |
| 门店资格细分 | [析] 兼顾品牌统一推广与门店经营边界 | 跨店订单归属更复杂 |
| 规则延迟生效 | [析] 避免频繁切换扰动归属 | 需要明确生效时间和影响范围 |

## 8 结论与待验证项

[析] 微盟最有研究价值的是“关系分销规则与实际分账怎样衔接”，同时是本批次最需要版本核验的产品之一。旧新文档和产品线混杂，结论必须带范围。

| 优先级 | 验证用例 | 验收证据 |
|---|---|---|
| P0 | 同一客户在两微客间切换、24小时到期 | 关系历史、订单归属 |
| P0 | 自购开关与邀请人奖励组合 | 实际受益人及金额 |
| P0 | 微信失败后线下补付 | 两条资金记录与防重机制 |
| P0 | 奖励类型重置时已有订单 | 历史规则快照、余额处理 |
| P1 | 新增规格未配奖励 | 阻断/警告与佣金结果 |
| P1 | API 重复创建、权限撤销 | 错误码、身份、审计 |
