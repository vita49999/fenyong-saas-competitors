# 八款 SaaS 横向对比总览

版本：公开证据版 v1。资料检索与编写：北京时间2026-10-13至14。证据状态见 [覆盖矩阵](10-证据覆盖矩阵.md)，实际交付边界见 [阅读说明](00-阅读说明与完成度.md)。

## 一、先区分四种产品形态

[析] 八款产品并非同质替代品。最重要的差别是它们管理哪类关系、掌握哪类业务事实，以及谁负责付款。

| 产品 | 本次研究主线 | 核心业务对象 | 最值得研究的设计问题 | 单款报告 |
|---|---|---|---|---|
| 有赞 | 商城分销员 | 分销员、客户绑定、订单、佣金 | 绑客竞争与售后结佣 | [有赞](01-有赞.md) |
| 纷享销客 | 渠道PRM/代理通 | 企业互联、伙伴、客户报备、商机、订单 | 跨企业协作与权限 | [纷享销客](02-纷享销客.md) |
| 微盟 | 微客分销，导购邻接 | 微客、绑定/邀请关系、商品奖励、分账 | 多关系与支付异常接管 | [微盟](03-微盟.md) |
| Everflow | 多渠道伙伴营销 | Advertiser、Partner、Offer、Event、Invoice | 多事件归因与收入成本 | [Everflow](04-Everflow.md) |
| Awin | 联盟网络 | Programme、Publisher、Transaction、Payment | 多方验证与可付条件 | [Awin](05-Awin.md) |
| FirstPromoter | 订阅联盟 | Campaign、Promoter、Referral、Commission、Payout | 生命周期奖励与月度账期 | [FirstPromoter](06-FirstPromoter.md) |
| Tapfiliate | 自建联盟管理 | Program、Affiliate、Conversion、Commission、Balance | 审核、结算、外部付款一致性 | [Tapfiliate](07-Tapfiliate.md) |
| Rewardful | 订阅推荐 | Campaign、Affiliate、客户、Invoice、Commission | 实付事件与到期应付 | [Rewardful](08-Rewardful.md) |

[析] 四种形态分别为商城内关系分销（有赞、微盟）、B2B伙伴协作（纷享销客）、多渠道/网络型联盟经营（Everflow、Awin）、自建联盟和订阅推荐（FirstPromoter、Tapfiliate、Rewardful）。Everflow与Awin同组仅为比较视角：前者的平台运营结构与后者的网络服务责任仍不同。

## 二、业务链路的分叉点

```plaintext
                [外部伙伴带来业务贡献]
                           |
        +------------------+------------------+
        |                                     |
 [关系/报备主导]                         [追踪事件主导]
        |                                     |
 客户绑定/客户查重                      点击/优惠码/客户ID
        |                                     |
 商城订单或B2B商机                      转化或计费发票
        |                                     |
 退款/履约/业务审核                     验证/退款/佣金审核
        +------------------+------------------+
                           |
               [形成收益/应付，而非已到账]
                           |
                [到期 / 门槛 / 收款资格]
                           |
             +-------------+--------------+
             |                            |
       [平台/集成付款]                [外部付款]
             |                            |
       [回执和失败状态]             [文件/人工/API登记]
             +-------------+--------------+
                           |
                    [对账与异常修复]
```

[析] 纷享销客的主链路终点是交易协作和经营复盘，并没有充分证据证明原生联盟佣金发款闭环；它不能硬塞到所有产品共同的“佣金支付”末端。

## 三、归属与归因

| 产品 | 已验证的主要机制 | 不应推导的结论 | 来源 |
|---|---|---|---|
| 有赞 | [官] 有效期、保护期、抢客触发可配置 | 点击覆盖不等于所有场景最后点击 | [绑客规则](https://help.youzan.com/displaylist/detail_4_4-1-39927) |
| 纷享销客 | [官] 查重、客户报备、商机协同 | 报备不等于广告Cookie归因 | [业务场景](https://help.fxiaoke.com/83d7/91e3/a544/f329) |
| 微盟 | [官] 关系链/分享人优先；绑定与邀请不同 | 不同微商城/推广员规则不可混用 | [分销设置](https://help.weimob.com/details/1847) |
| Everflow | [官] 点击/优惠码优先与多级回退 | 多方法不保证缺失数据下准确 | [归因优先级](https://helpdesk.everflow.io/customer/everflows-conversion-attribution-priority) |
| Awin | [官] 计划、交易追踪和验证 | 本批未完整验证归因优先级 | [产品](https://www.awin.com/gb/advertisers) |
| FirstPromoter | [官] Click→Referral邮箱/UID→Sales | 计费接通不等于推荐身份接通 | [追踪链路](https://docs.firstpromoter.com/how-it-works) |
| Tapfiliate | [官] Cookie、优惠码、S2S | Cookie时长范围有官方文档差异 | [集成](https://support.tapfiliate.com/en/articles/12960344-understanding-how-the-integration-works) |
| Rewardful | [官] 推荐客户与已付Invoice关联 | 客户续费不等于每次重新最后点击 | [入门](https://help.rewardful.com/en/articles/2044650-what-is-rewardful) |

[析] 客户归属是持续服务和渠道保护机制，广告归因是贡献识别机制。二者可以相关，但不能只设计一个“来源人”字段承担所有含义。至少要区分推荐人、客户服务归属、邀请人、订单受益人和实际收款人。

## 四、计佣与退款：不要只比较“支持百分比”

| 产品 | 计价/收益特征 | 退款或异常已验证点 | 关键缺口 |
|---|---|---|---|
| 有赞 | [官] 订单实付净额、商品/人员等级 | 结算前退款扣除；结算后可能不追回 | 当前版本全部资金渠道 |
| 纷享销客 | [官] 价目表、允销、折扣、费用/返利邻接 | 报备和审批，非佣金冲正证据 | 原生返利/佣金结算边界 |
| 微盟 | [官] 按比例/数量、多奖励介质 | 有返还算法、分账失败转线下 | 自购、版本、已提现追偿 |
| Everflow | [官] 每事件收入与Payout分别定义 | 手工审批、重复开关、限额Pending | 退款全链和历史重算 |
| Awin | [官] commission groups，按商品/客群等 | Pending→批准/拒绝及原因 | 部分退款与tracking fee退费 |
| FirstPromoter | [官] 固定/比例、时长/次数、首期差异 | 自动负佣金；Braintree退款例外 | 已付后追偿、proration |
| Tapfiliate | [官] 循环、分组、商品/类别佣金 | 拒绝/修改佣金导致负余额 | 离场伙伴追偿和幂等 |
| Rewardful | [官] 已付Invoice和续费 | 全额/部分退款、升降级调整 | 已付后冲正、币种舍入 |

[析] 真正决定复杂度的维度是：基数是否含税/折扣/运费、奖励期间、触发事件、规则优先级、金额精度、退款时点、历史规则版本以及付款是否已经执行。公开资料没有覆盖的字段留作待验，不以惯例补齐。

## 五、资金状态和付款责任

| 产品 | 关键状态/节点 | 实际付款路径 | 最易误读的地方 | 证据 |
|---|---|---|---|---|
| 有赞 | 待结算、已结算、提现 | 自动结算或商家线下 | 结算与提现到账不同 | [结算规则](https://help.youzan.com/displaylist/detail_5_5-2-31738) |
| 纷享销客 | 报备/商机/订单等各对象流程 | 订货支付与财务集成为邻接 | CRM闭环不代表佣金已付 | [渠道产品](https://www.fxiaoke.com/ap/product-outer/) |
| 微盟 | 奖励、分账、应付账单、提现 | 微信线上/线下人工 | 线上失败有线下接管 | [设置](https://help.weimob.com/details/1847) |
| Everflow | Invoice Status与Payment Status | 集成通道或外部登记 | Mark as Paid不转账；None通道例外 | [付款](https://helpdesk.everflow.io/customer/processing-partner-payments) |
| Awin | Pending review→Approved→Payable→付款 | 网络付款批次 | Approved不等于Payable | [状态与付款](https://success.awin.com/articles/en_US/Knowledge/Understanding-Transaction-Status-and-Payment-Process) |
| FirstPromoter | Commission→月度Payout→到期/门槛 | 集成/托管/外部路径 | NET-30是月末后，不是每单后 | [Payouts](https://help.firstpromoter.com/en/articles/9019492-how-payouts-work-in-firstpromoter) |
| Tapfiliate | Pending→Approved→Balance→Settled | CSV外部、API自建、Trolley | Settled不证明实际付款 | [付款流程](https://support.tapfiliate.com/en/articles/13272686-the-payout-process-settling-balances-and-generating-a-payout-file) |
| Rewardful | Pending→Due→Paid；Voided分支 | 批量或Managed Payouts | 门槛与到期共同决定Due | [入门](https://help.rewardful.com/en/articles/2044650-what-is-rewardful) |

[析] 对所有产品应使用同一笔业务贯穿验证：“产生佣金→审核→到期→纳入付款→资金发出→资金到账→退款冲正”。同名 Paid/Settled 在不同系统含义不同，横向对比必须比较动作和凭证，不能直接对齐标签。

## 六、权限与开放性

[析] 纷享销客当前公开证据最清楚地表达了外部企业、人员、对象、字段和数据范围的权限分层；这是证据覆盖结论，不是证明其他七款缺少权限。

| 产品 | 已阅读开放证据 | 核验边界 |
|---|---|---|
| 有赞 | [官] 官方招募文档确认开放接口导入 | 未完成全量接口契约 |
| 纷享销客 | [官] APL渠道场景函数摘要 | APL函数不等于外部REST全量 |
| 微盟 | [官] distributor/create，ACCESS_TOKEN | 套餐/版本、其他资金接口待验 |
| Everflow | [官] Network/Affiliate/Advertiser REST、SDK、Webhooks | 凭证权限、限流/幂等待实测 |
| Awin | [官] API与套餐、Conversion API例外 | 交易验证及支付API细节待验 |
| FirstPromoter | [官] 点击/Referral/Sales、API、Webhook主题 | 签名/重试参数未全读 |
| Tapfiliate | [官] REST更新佣金与付款登记流程 | 鉴权示例差异、防重待验 |
| Rewardful | [官] REST Basic Auth、Webhook、标付API | 回调完整性与签名待验 |

来源在各单款第五章就近列出，矩阵与原报告使用相同证据编号。

## 七、商业模式与费用口径

所有价格是已引用官方页的观察值，币种/地区不能换算后简单排序。

| 产品 | 当前可确认口径 | 费用分析要点 |
|---|---|---|
| 有赞 | [官] 商城及分销进阶能力包；统一价未验 | 基础商城、分销增强与资金服务分开询价 |
| 纷享销客 | [待] 代理通独立价及实施范围 | CRM/PaaS、外部用户、实施和集成成本 |
| 微盟 | [官] 分产品线/套餐；现行统一价未验 | 不拿旧微盟客佣金费率代表所有模块 |
| Everflow | [官] 平台与Pay费用另有口径；平台价未确认 | 支付量、跨境和FX、实施成本 |
| Awin英国 | [官] £99+VAT/月+3.5%，Accelerate £199起+2.5% | 交易额tracking fee与伙伴佣金另算 |
| FirstPromoter | [官] $49/$99/$149月付页面 | 按联盟收入分档，付款服务额外条件 |
| Tapfiliate | [官] $89/$179月付，企业询价 | 点击/转化配额、超额、外部支付 |
| Rewardful | [官] $49/$99/$149起，归因收入费0% | Managed Payouts商家3%另算 |

[析] 三种常见收费基数分别为平台订阅、归因交易/收入、实际佣金付款额。任何“0手续费”结论都必须说明指的是哪一种。企业实施、税费、汇率和支付通道费用不因平台费为0而消失。定价来源见各报告第一/六章。

## 八、面向产品经理的机制库

以下均为[析]，是跨产品提炼而非某款完整实现的承诺。

| 设计问题 | 参考对象 | 可借鉴机制 | 价值与适用边界 |
|---|---|---|---|
| 多人竞争同一客户 | 有赞/微盟 | 关系有效期、保护期、分享归因分开 | 适合存在持续服务归属的业务 |
| 外部企业参与销售 | 纷享销客 | 外部角色、数据范围、报备+阶段任务 | 适合B2B，不能用Cookie代替治理 |
| 一个漏斗多次计价 | Everflow | 事件独立、收入与Payout分别配置 | 多阶段价值明确时有效 |
| 交易有效但钱未可付 | Awin | 验证/可付/付款分层+阻塞原因 | 多方链路必须交代责任方 |
| 订阅长期收益 | FirstPromoter | 时长/次数、分段费率、个体覆盖 | 月付年付必须测试终止边界 |
| 外部支付一致性 | Tapfiliate | 付款后登记、取消恢复、负余额 | 要有防重及补偿机制 |
| 轻量付款工作台 | Rewardful | Pending/Due/Paid、门槛和退款窗口 | 不能用单状态隐藏原因 |
| 退出后历史权益 | 有赞 | 身份生命周期与资金权益分离 | 余额可达性、认证和未完业务要完整 |

## 九、统一补验计划

| 优先级 | 统一用例 | 为什么必须验证 |
|---|---|---|
| P0 | A链接+B优惠码/绑定关系冲突 | 检查归属优先级及解释 |
| P0 | 全额/部分退款，分别发生于审核前、付款前、付款后 | 区分冲正、负余额与真实追回 |
| P0 | 付款失败、资料缺失、重试和外部标付 | 避免账面状态冒充真实到账 |
| P0 | 更改规则后重看历史订单 | 检查规则快照和追溯 |
| P0 | 伙伴退出/停用时仍有未结款 | 检查权益和历史访问 |
| P1 | API重复通知、乱序、超时重试 | 防重复计佣与重复付款 |
| P1 | 运营/财务/伙伴多角色越权 | 检查服务端权限而非菜单隐藏 |
| P1 | 多币种、折扣、税额、四舍五入 | 确认会计口径和金额一致性 |

[析] 不给八款产品做“功能最多即最好”的总分。当前可读研究已经形成；付费版本全量盘点、租户操作和API/资金实测仍是下一阶段，逐项证据缺口见矩阵。
