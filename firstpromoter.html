FirstPromoter：围绕订阅账单组织奖励与付款

1 产品概述与商业模式

官方验证 FirstPromoter 以 Campaign 组织推广者，每个 Campaign 有自己的奖励、注册页、联盟门户和邮件；同一推广者可以加入多个 Campaign，并拥有对应链接。Campaign 配置（P1）。

官方验证 原生计费集成包括 Stripe、Paddle、Chargebee、Recurly、Braintree；可以处理比例或固定奖励及循环计佣。循环佣金（P2）。

分析推断 核心场景是商家自建订阅推荐/联盟项目，而非加入一个成熟广告联盟网络。商家经营 Campaign，Promoter 推广，Referral 是被推荐的客户，实际计费事件产生佣金。

4 官方真实界面展示与交互分析

官方验证 来源：奖励与佣金产品页。这是官网发布的界面展示图，非本次租户截图。已按实际画面确认：图中是 Campaign 配置，不能因为所在章节名称就称作“佣金期限配置”。

分析推断 活动名、默认链接和 Cookie 有效期在同一区域，有利于活动负责人检查基本追踪条件。“自动批准推广者”与“自动批准佣金”是不同开关，产品培训应明确区分身份准入和收益审核。

官方验证 同一官方产品页发布的图，实际内容是 Stripe Payouts，并非图片文件名暗示的 coupon。展示受限 API key 与连接状态。分析推断 清楚列出所需权限有助于接入，但“已连接”不证明资金可付，应进一步检查收款方 onboarding、余额与到账。待验证 当前产品对多账号切换的未完成佣金迁移提示需验证。

官方验证 本次2026-10-15从P7官方Stripe集成帮助下载的真实界面图，官方图片文件名包含2024-03-29；显示连接状态和测试模式，访问日期不是界面版本日期。分析推断 用显式连接状态降低接入不确定性，但绿色已连接不能证明所有销售都已正确匹配Referral，仍需完整测试交易。

5 对象、关系、状态、规则、异常、权限、资金、API

5.1 对象关系

分析推断 一人多 Campaign 的关系意味着奖励属于活动上下文，不应把推广者只有一个佣金率作为数据模型假设。

5.2 计佣、审核与账期

官方验证 比例或固定奖励可以按客户生命周期、时长或收费次数终止；可以配置前后两段不同费率。P2。

官方验证 产品页明确：计佣来自确认的计费事件；0金额账单不生成佣金，但 Referral 仍可追踪。默认自动批准，也可人工审核或设金额阈值；没有基于计时器的佣金自动批准，延迟付款应放到 payout terms。P4。

官方验证 Payout 为某个月佣金的聚合；默认 NET-30 示例是3月佣金在4月30日支付，不是每笔交易发生后30天。Custom 无固定到期日，最低金额可跨月累计。P5。分析推断 审核、账期和门槛分别约束真实性、风险时间和支付效率。

5.3 异常、权限与资金

官方验证 退款产生负佣金并减少未付余额；Braintree 的退款需人工处理。Stripe 集成文档确认销售、退款、升级与取消同步，并提供 Test mode。P4、P7。

试用/0元账单 Referral 与付佣分离 后续首付是否沿用正确活动
部分退款 官方有退款负佣金机制 舍入、原币、已付后负余额

分析推断 商家承担佣金政策和付款责任；原生计费追踪不代表所有支付通道都自动付款。待验证 托管 payout 资格、费用、税表适用地区以及团队内审核/付款分权需另验。

5.4 API 与系统机制

官方验证 官方文档将点击、Referral 和 Sales 追踪分开；Referral 需要邮箱或 UID 匹配计费客户，其他计费系统可通过 API 发送销售。How it works（P3）。开发文档还提供 Webhooks、事件类型、payload、投递和重试主题。文档（P8）。

分析推断 应验收“前端推荐身份→计费客户→收费事件→佣金”的连接完整性。仅集成账单回调而没有 Referral 身份，无法保证正确归因。待验证 API 鉴权头、事件唯一键、重试上限、签名和回调乱序未逐项验证，报告不列猜测值。

6 产品经营与商业模式

官方验证 定价页观察：Starter $49/月、Business $99/月、Enterprise $149/月；分别对应月度联盟收入≤$5,000、≤$15,000、>$15,000的页面描述；有年付与14天试用。定价（P6）。Enterprise 具体商业条件仍应询价。

分析推断 按联盟收入分档使软件价值与客户增长关联；活动和个体覆盖满足从标准联盟到重点伙伴议价。奖励复杂性、托管支付与集成构成扩展价值。没有证据证明这些能力能独立带来某个平均增收比例。

7 产品经理可借鉴机制

机制 原因与价值 局限
Campaign 默认+个体覆盖 分析推断 大多数规则一致，少数需议价 覆盖多了难审计，需清单
时长与次数分开 分析推断 月付年付不能只按一个时间维度处理 暂停/恢复和计费调整有边界
审核与付款等待分开 分析推断 有效性确认不必等于立刻付款 用户容易误解 Approved
退款负佣金 分析推断 保留原收益并显示抵减，容易解释 已付款仍需追偿/抵扣机制
非现金权益用履约通知 分析推断 软件算奖、商家应用发权益 回调失败可能已算奖未兑现

8 结论与待验证项

分析推断 FirstPromoter 适合研究订阅生命周期佣金、活动隔离和按月付款组织；比泛化“支持循环佣金”更有价值的是收费次数、时长、规则覆盖和退款抵减如何结合。

P0 年付与月付、按次数和按月数规则 截止边界、首次/后续费率
P0 已批准未付及已付款后的退款 负佣金、余额和付款恢复
